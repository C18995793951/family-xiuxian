# 家族修仙录（个人主角版）

在浏览器中运行的中文修仙文字游戏。你扮演一个刚满十六岁的修士，从炼气一层走到寿元耗尽或死于非命。没有固定主线，剧情由你的行动和世界的变化推出来；世界规则严格执行。

> **当前进度：个人主角改造 · 阶段 1（主角最小循环）**。改造方案见项目里的《家族修仙录改造方案：个人主角》。旧的“经营家族”版本保留在分支 `claude/ai-head`（含 DeepSeek 润色与 AI 家主托管）。

## 运行方式

- 双击 `dist/family-xiuxian.html`，用最新版 Chrome 或 Edge 打开即可，手机浏览器也能玩。
- 只有一个文件，不需要联网，也不发出任何网络请求。

## 怎么玩

1. **开局**：选出身（山野散修、小族子弟、宗门外门弟子），姓名和种子可留空。种子相同、选择相同，这一生就逐位相同。小族子弟的家族以你的姓氏命名。
2. **行动**：每个行动都消耗时间。修炼 1 个月到闭关 10 年；在当地游历 10 天或 1 个月；沿道路赶往相邻地点；在坊市打杂或在本门本族做差事挣灵石；在坊市买卖；拜访在场的人、向交情够的前辈请教；服药、改修功法。
3. **时间与世界**：时间按天推进，跨月结算主角的伤势和闭关打扰，跨年结算整个世界：约 80 个人物各自修炼、冲关、老死或意外身亡，势力招新、换掌门，坊市换货。
4. **遭遇**：遇上妖兽、劫修或古修洞府时会弹出决断面板，每个选项写明代价、风险和成功率怎么算。成败由规则掷骰决定。可以用数字键选择。
5. **突破**：炼气一至八层修满自动晋升；冲击筑基、金丹和小境界需要你决定，决定前列出成功率的每一项修正和失败身死的概率。
6. **地图**：约 18 个地点（坊市、宗门、家族驻地、山野、险地），各有灵气与危险度。宗门和家族驻地只对自己人开放灵气。
7. **结局**：主角身故时给出生平和评定。

## 两条设计原则

- **不强行制造奇遇。** 遭遇只在游历、赶路、闭关被打扰时才有机会出现，多数时候什么都不发生；古修洞府这类奇遇五年内最多一次。
- **不保证主角幸运。** 游历、冲关、结交、请教都可能一无所获，成败只看规则掷骰。

两条原则都有自动化统计检验（见下方测试 9、10）。

## 存档

- 3 个手动槽位加 1 个自动存档，每次行动后自动保存。
- 优先 IndexedDB，不可用时降级 localStorage；都不可用时请用导出。
- 导出 `.json` 文件或压缩文本（`FXZ1:` 开头），导入同样支持两种。
- 读档依次检查：版本 → 校验和 → 结构 → 引用完整性。旧版“经营家族”存档会被明确拒绝。
- 存档里预留了 `aiLog`：阶段 3 起，AI 生成的事件原文会记在这里，读档重放时用记录而不重新调用，保证可复现。

## 数值配置

所有数值、概率、名字库和文本模板都在 `src/core/config.js`，遭遇定义在 `src/core/encounters.js`。逻辑代码里不写死平衡数值。

## 开发与测试

```
src/core/   模拟核心（不访问 DOM、不联网、不调用 Math.random / Date.now，可在 Node 中无头运行）
  config      数值与文本
  rng         种子随机数
  history     时间换算、结构化历史、叙事流、生平
  characters  人物、寿元、伤势、关系
  cultivation 修炼速度与突破（主角与 NPC 共用）
  world       世界生成：地点、道路、势力、人物、坊市
  events      待决事件的绑定、视图与结算
  encounters  斗法检定与遭遇定义
  sim         开局、时间推进、世界逐年模拟、结局、自检
  actions     主角行动清单与执行
  save        序列化与校验
  api         界面与测试共用的公开接口
src/ui/     界面与存储适配器
build.js    把 src/ 内联成 dist/family-xiuxian.html
test/       自动化测试、平衡报告、预设策略、界面冒烟测试
```

```bash
node build.js                 # 生成 dist/family-xiuxian.html
node test/run-tests.js        # 自动化测试（13 项）
node test/run-tests.js --quick
node test/balance.js --seeds 40   # 平衡报告
node test/ui-smoke.js         # 浏览器冒烟测试（需要 Playwright）
```
